# Kinktionary

A consent-first glossary and community app for adults, built with Flutter for Android and iOS.

## Features
- Searchable A–Z glossary with category filters (133 terms)
- Guided starter paths ("Start here", "Talking it through", and more)
- Safety and consent basics
- Bookmarks and private notes, stored on-device only
- Community posts, replies, likes, and friend requests for signed-in users
- Public profiles with post activity
- 18+ age gate on first launch

## Local development

Install Flutter, connect a device, and run these commands from this directory:

```sh
flutter pub get
flutter analyze
flutter test
flutter run
```

## Friend test APK

Create a debug-signed APK with:

```sh
flutter build apk --release --target-platform android-arm64 \
  --dart-define=APP_CHECK_DEBUG=true \
  --dart-define=APP_CHECK_DEBUG_TOKEN="$APP_CHECK_DEBUG_TOKEN"
```

Set `APP_CHECK_DEBUG_TOKEN` to your own App Check debug token before building; do not commit or share it. Register the token with `firebase appcheck:debugtokens:create <token> --app <androidAppId> --display-name friend-testers`. The output is `build/app/outputs/flutter-apk/app-release.apk`. This is an optimized, debug-signed arm64 test build. Anyone with the APK can extract its token, so delete it in the Firebase Console when testing ends. Do not publish this APK. A production build omits both defines, uses Play Integrity, and must be signed with a private release key.

Signed-in text posts, replies, and likes are stored in Firestore. Profiles and friend requests use Firestore under `users`; profile photos use Cloud Storage. Guest posts and private glossary notes remain on-device.

## Editing content
Your term files are the source of truth. Edit them, then rebuild:

```
python3 tools/build_terms.py      # needs PyYAML: pip install pyyaml
```

- `data_source/yaml/*.yml`: your Categories, Genders, Orientations and Roles terms. Each section becomes a category in the app.
- `data_source/extras.json`: extra terms (consent, community, activities), plus optional `details`, `related`, `safetyNote` and `draft` fields that can be attached to any term id. A YAML term's name and definition always win; extras only fill in what's missing.
- `assets/data/terms.json`: generated output the app reads. Don't edit by hand.
- `assets/data/paths.json`: guided learning paths (`termIds` must be real term ids; the build script checks this).
- `assets/data/consent.json`: safety and consent topics.

Terms marked `"draft": true` show a "Draft definition" badge in the app until you remove the flag.

## Background wallpaper
The dark tiled wallpaper is generated by `tools/arrange_background.py` (needs Pillow and OpenCV) from `assets/images/background.webp` into `assets/images/background_items.webp`. `tools/make_pattern.py` generates the light-theme tile `assets/images/pattern_tile.png`.

The splash uses the same wallpaper and the supplied A-mark source at `assets/images/splash_source.png`.

## Before you publish
- Have the content reviewed by experienced educators from the kink community and, for health and safety notes, a qualified professional.
- Check App Store and Google Play policies for sexual-content apps and set the age rating accordingly. Apple and Google both have specific rules, so read them early.
- Publish a privacy policy that describes account, profile, community, friend-request, and profile-photo data stored by Firebase.
